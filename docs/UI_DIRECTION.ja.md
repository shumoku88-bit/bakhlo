# BakhloのUI方針

LOAMで検証された家計の意味・機能・操作習慣を土台に、Bonsaiの能力を生かして、
綺麗で派手ではないモダンなTUIへ磨く。Calendar Home、画面の階層、キー操作、
フォーカス、選択・戻る・確認の流れを参照し、Bakhloの実際の使い心地を基準に整える。
Bakhloはまだ家計簿として運用していない。旧UIの配置、テーマ、内部APIとの後方互換性は
要求せず、不要な表示や未使用の仕組みは削除する。LOAMの本番データや記帳先の切替は別の判断。

## 職人的な品質の基準

- 余白、列の整列、文字の強弱で情報の順序を作る。色と枠は意味がある場所に絞る。
- フォーカス・選択・入力カーソルを読み分けられ、操作した対象が常に見える。
  端の移動、ページ送り、戻ったときの位置、下書きの再開まで一貫させる。
- 入力や短い通知でレイアウトを揺らさない。長い警告では必要な内容を残し、
  読める範囲と省略・スクロールを正直に表示する。
- フローティング表示から狭い端末への切替でも、対象・下書き・操作の意味を保つ。
  全画面へのフォールバックと、読めない確認内容の確定拒否を両立させる。
- 長い金額、符号、通貨、日本語の科目名、文字幅、枠の接合部、カーソル末尾などの
  小さい違和感を実際の描画と操作で確認する。装飾の量を完成度の指標にしない。
- Bonsaiの状態・入力・描画の組み立てを生かし、必要な場所から自然な構成へ整える。
  共通化の範囲はLOAMのリサーチと実際の用途を確認して判断する。
- 代表的な生活操作を実物で繰り返して磨く。テスト成功と人間の使い心地の受入を区別する。

## 言語と操作の基準

- 新UIは英語を先に作る。`Home` / `Calendar` / `Detail` / `Commands` / `Record` /
  `Actual` / `Scheduled` / `Balances` / `Daily Pace`等はLOAMと同じ英語表記を使う。
- 日本語UIを用意するかは未定。英語先行を、日本語切替の実装予定として扱わない。
- Bonsaiを先行して実装する。Nottyを排除する決定ではなく、後から新UIのNotty版を追加する選択肢がある。
- 共通化は目的にしない。LOAM側の「共有が有効な範囲／有害な範囲」のリサーチを確認してから
  境界を判断する。似た表示でも異なる操作・意味を万能フォームへ押し込まない。
- UIの固定文言と、科目の表示名・メモ・安定ID等の台帳データを分ける。
  データを英語へ書き換えない。拒否理由の判断は表示文言ではなく安定した原因や型で行う。
- Calendar HomeのDay / Month / Year、選択日の画面、階層Commands、操作別画面を採用する。
  Homeの`q`は終了、子画面の`q` / `Esc`は一段戻る。LOAMの表示・操作契約を実装前にソースで確認する。
- `Record`の入力・候補・全体確認・確定と、`Actual` / `Scheduled`の対象選択・詳細・操作を揃える。
  確定キーも旧Bakhloの独自規則を永久互換にせず、LOAMの明示的な確認操作を基準にする。

## 表示規則

以下は改修の目標と判断基準であり、全画面の実装済み機能を列挙するものではない。
実装範囲は現在のソースと変更ごとの検証で確認する。

- 初期値のTerminalテーマでは背景・通常文字とANSIアクセント色を端末設定に委ね、端末の
  ライト／ダークやカスタム配色に従う。編集枠も固定色を混ぜない。オリジナルのBakhlo Light／Darkへ
  切替可能とし、テーマは台帳と独立したUI設定へ保存する。補助情報、非アクティブ枠、操作の説明は控えめにする。
  アクセントはフォーカス枠とアクティブな選択に絞り、見出しや通知ごとに色を増やさない。
- 細い丸角の枠を使い、隣接する枠の間に余白を置く。整列と情報の順序で読みやすくする。
  日付・対象・範囲は短い文脈として置き、詳細では金額と内訳を先に、ID等を補助情報として置く。
- 選択、検索、短い通知で枠と一覧の高さを動かさない。操作は文脈に応じた固定の下部領域へ置く。
  フィードバック行は空でも確保し、日本語や長い原因を表示幅で折り返す。
  表示しきれない場合は省略を明示し、全文へ到達する手段を残す。
- フォーカスと選択を区別する。非アクティブ一覧も選択位置を保持し、強い背景はアクティブ側だけに使う。
  狭い端末では操作対象に全幅を渡す。選択追従、ページ移動、詳細スクロールは実際の可視行数に合わせる。
- 数量は符号・通貨・桁区切りを明示し、右寄せで揃える。桁を途中で切って別の金額に見せない。
  一覧に収まらない値は詳細へ誘導し、詳細では完全な値を読めるようにする。不明とゼロ、異なる通貨を混同しない。
- 入力ラベルは揃え、編集中の値と文字カーソルを明確にする。長い入力は編集中の末尾を見せ、保存値を切らない。
  picker、検索、詳細、プレビューは一時的なpaneにし、閉じたら下書きと元の選択へ戻る。

## 守る境界と検証

表示状態は台帳の意味や保存権限にならない。プレビューを開く操作、閲覧、picker選択は保存しない。
確定は既存の検査・publication経路に通し、競合・結果不明の停止と下書き保護を維持する。
通知を控えめにすることは、安全上必要な警告を隠すことではない。

合成台帳で、通常・狭い・低い端末、日本語、長文、巨大数量、空一覧、不明量、リサイズ、
取消・確定・再起動を必要な範囲で確認する。新依存や別の保存経路はUI統一のために導入しない。
現在の起動先は先行実装のBonsai。旧Notty画面と重複するUI試作は削除済みだが、
新UIでのNotty追加を排除していない。
未実装の会計機能を偽の数字や名前からの役割推測で埋めない。操作互換と会計機能の未接続を明示的に区別する。

LOAMの参考箇所は [TUI.md](../../loam/docs/TUI.md)、[画面別進捗](../../loam/docs/TUI_NON_BUDGET_WORKLIST.md) と
共通の [Layout.lean](../../loam/Loam/Tui/Layout.lean)。UI互換を目指すが、LOAMの研究基盤や保存実装の移植を意味しない。
前段の共通描画の改修は土台であり、Calendarや英語版の互換完成を証明するものではない。
