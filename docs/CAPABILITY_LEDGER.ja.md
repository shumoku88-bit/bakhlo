# Bakhlo 機能・保証台帳

最終棚卸し: **2026-10-08**／Bakhlo **main `12335186310bc606e0741dec49de9e9f23391234`** を読んだ時点。
これは実装・資料の照合による暫定台帳であり、この更新のためにビルドやテストを実行したという意味ではない。

## この台帳の目的

**LOAMで獲得した会計上の設計資産を失わず、Bakhloでは実際に必要になった機能だけを実装する。**

- 「コアが表現・検査できる」「日常のデータ形式に残せる」「画面から使える」「本番で安全に運用できる」は別の主張。
- LOAMの研究・証明・実運用の成果は**引き継ぐべき知見**であって、OCaml実装の正しさを自動的に証明しない。
- この台帳は将来の全機能を先に実装するためのTODO表ではない。未実装でも、保持すべき意味と調べた反例を記録する。
- **当面の家計正データはLOAM。Bakhloの試用可能は運用切替認定ではない。** 個人の実データ、金額、秘密情報はこの公開資料に書かない。

詳しい画面ごとの生活操作は [LOAM切替チェックリスト](CUTOVER_CHECKLIST.ja.md)、実験条件と限界は [検証記録](VERIFICATION.md)、意味の禁止事項は [意味の契約](SEMANTIC_CONTRACT.md)、現在の作業は [HANDOFF](HANDOFF.md) が担当する。ここではその**機能横断の見取り図**だけを保つ。

| ID | LOAMから残す研究成果・区別 | LOAMの状態 | Bakhloの状態 | 実装する契機 |

**X01〜X05は「LOAMが証券管理を完成させた」という宣言ではない。** 有用な反例・独立情報・設計上の圧力を残している。特に「グラフで全てのLotIdを再構成できる」とも「必ずLotオブジェクトが必要」ともまだ決めない。将来の最小実装は、そのときの実際の問い合わせと証拠に基づいて決める。

## 4. 言い切ってよいこと／いけないこと

- **言える**：Bakhloに対応するOCamlの型・API・テストソースが存在する。限定したDaily形式で予定・予算・日割り等の計算と保持ができる。
- **条件付きで言える**：試用TUIでは普通の記帳、訂正、予定支払い、科目選択等を試せる。これは本番データでの故障耐性の認定ではない。
- **まだ言えない**：LOAMの全会計情報に互換、LOAMの形式的保証をOCamlへ証明付きで移植済み、株式会計が完成、電源断から必ず復旧、MirageOS上で家計簿運用可能、Bakhloへの切替完了。
- **新機能の追加時に守る**：新しい独立した証拠が必要なら追加する。既存の中立Coreだけで足りるなら増やさない。足りない条件を推測で埋めない。

### 将来この台帳を更新する最小手順

1. 変わった **ID行だけ**更新し、正確な適用範囲を書く。全機能の一斉実装表にしない。
2. 「意味が表現できた」「APIができた」「Dailyで保存・再読込できた」「UIで操作できた」「故障を含む運用認定」の**どの段階**を進めたかだけ記録する。
3. 主張を強くしたときは、対象のソース・テスト・実行した環境・日付・失敗した例を該当PRまたは [VERIFICATION.md](VERIFICATION.md) に残す。未実行を成功扱いしない。
4. LOAMとの意味の差が意図的なら明記し、データを損失なく移す必要があるかを判断する。元の正データを黙って修正しない。
5. 使う要求がなければ **「研究資産として保持／当面実装しない」** が健全な結論。
