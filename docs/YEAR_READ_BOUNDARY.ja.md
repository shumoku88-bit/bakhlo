# 年度版読込・検証境界（PR 1）

`Bakhlo_sexp.Year_read` は明示的に呼ぶ検証部品。**本番利用可能な年度別
ストレージではない**。既定の単一S式、CLI、TUI、正式な正データ形式は変更しない。
研究参照は `research/canonical-storage-checkpoint@268835a` の課題A。
研究用テスト・保存方式・ベンチマークは移植しない。

## 信頼境界

`Make` の入力 `VERIFIED_SELECTION_SOURCE` は、権威ある選択状態の検証と
全年度の一体スナップショット取得を担う。その実装は今回提供しない。
自己申告ヘッダー・未検証manifest・任意の選択レコードを返す実装は契約違反。
抽象インターフェースは真正性の証明ではなく、未実装の責任境界を表す。

セッション開始時に世代・年度・revision・重複年度を検査する。読込時は
固定した選択と原本の世代・年度・revisionを照合し、**取得した全バイト列から**
fingerprintを再計算する。その後、既存 `Daily_book.of_string` でCoreの入場検査を
通す。明細は当該暦年に限る（予定日は翌年でもよい）。不明・欠落・破損・
混合世代・不一致は `error` の各コンストラクタで拒否し、代替原本に逃げない。

fingerprint は `Stdlib.Digest` のMD5による偶発的変更の識別であり、暗号学的な
真正性・悪意ある改ざん耐性は保証しない。未検証ハッシュ文字列を取り込むAPIは
ない。選択状態の供給源自身の検証・信頼は、ハッシュ一致で代替できない。

## 繰越とCore

`year_version` / `carry_forward` / `annual_read` は抽象型。繰越を任意の数量から
作る経路はなく、検証・入場済み前年原本からのみ導出する。依存元の年度・revision・
fingerprintとセッション同一性を、当年読込の前に検証する。別セッションでは再読込・
再導出する。既存セッションは開始時の選択を使い続ける（最新HEADを主張しない）。

`carry_balance` は既存 `Current_quantity_query.query` による**前年末の回答**。
Exact / Zero-origin / Known-present / Unknownを保持し、原点支持でも非ゼロなら
Exact。繰越を独立観測としてCoreへ注入しない。`current_book` は当年単体の入場済み
台帳であり、繰越込みの残高ではない。Coreには年度・保存世代を追加していない。

## 残るもの

- 検証済み選択状態の実供給源、年度別wire形式、永続化された繰越の検証。
- 当年とのエフェメラル合成、root cut、CrossYearResolver、跨年度予定完了。
  未解決参照のある単独年度は現行Coreが拒否する。省略・推測して通さない。
- 年度別保存、manifest更新、一体公開、排他、fsync、障害復旧、GC。
- 性能認定と運用認定。研究の120msは本体の達成値ではない。

契約テストは合成データのみ。原本バイト列照合、前年訂正、選択障害、
セッション固定、混合世代、Core拒否、4分類、読取時のファイル不変を確認する。
供給源には書込操作を要求せず、既存の保存・回復経路にも接続しない。
