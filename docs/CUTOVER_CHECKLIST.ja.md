# LOAM → Bakhlo：機能棚卸しと乗り換え判定表

**状態：切替範囲を決めるための初版。最低限の範囲はまだ確定していない。**

## この一覧の役割

「LOAM全部を実装する」でも「少し動いたので乗り換える」でもなく、
**どの生活操作ができれば普段の記帳先をBakhloに替えるか**を、人間とpitが同じ表で決める。
必要な表現力は保ち、LOAMの研究機構・ファイル構成・画面配置まで再現する義務にはしない。

ユーザーが具体的に挙げた検討の核は、次の三つ。

- **複数ポスティング入力**：一つの取引を複数の口座・科目に分けて記録できる。
- **支払い予定の管理と実績化**：予定を管理し、実際の支払いへつなげられる。
- **残高の確認**：必要な口座・通貨の残高を確認できる。

この三つの細部と、それ以外の切替条件は下の表で決める。
未決定をpitが勝手に「不要」または「全部必須」に変えない。
製品として必要な予定・予算・レポートと、**最初の切替日に必要な範囲**も分ける。

## 調査範囲と読み方

- LOAM：`f82f4c45498ce9b3c51a76acb7189588a5f74718` の文書、実行入口、操作・表示・発行境界を読んだ。
- Bakhlo：`e1e010818ef02d1b3ea6b38d4ea276cdb8c26532` に加え、現在の未コミットのDaily_book／TUI接続を確認。
- **実データ・私的設定は調べていない。LOAMのビルド・起動・移行もしていない。**
  したがって「この家庭で使っているか」はユーザーが決める。機能の存在と使用実態を混同しない。
- 古い調査文書の「未実装」より、現在の実行入口と操作元を優先した。
  たとえば現在のReportsにはIncome & Expense、役割別Balances、Multicurrency Spendがある。
- 主たる比較対象は **`tools/tui [notty|bonsai]` と `bakhlo-daily`**。
  旧Book用の `record`／`exchange` CLIが持つ能力は、別形式のままなのでDaily TUIの対応済みに数えない。

Bakhlo欄の意味：

| 表記 | 意味 |
| --- | --- |
| 試用可 | 新しい日常TUIから操作できる。実運用への切替・耐久保存の認定ではない |
| 一部 | 使える範囲と不足を同じ欄に明記した |
| データ／検査のみ | 保存形式や検査はあるが、普通の画面操作につながっていない |
| 未接続 | LOAMの該当機能に相当する日常操作・回答が新しい台帳経路にない |
| 未調査 | 存在・接続を確認できていない。未実装と断定しない |

切替欄は実装の完了印ではなく、**範囲を選ぶ判断**。
「重点」は上のユーザー提示の検討対象で、必須範囲を確定した印ではない。
「必須候補」はpitの提案、「要判断」は未決定、「後で候補」は初回切替から外せそうな提案。
いずれも判断を変更できる。
根拠の `[L1]` 等は末尾の読み取り専用参照。

## 機能とは別に、データの持ち越しを決める

**新しい台帳が読めることは、全家庭データが移ったことではない。**
現在の候補作成は限定された読み取り・変換であり、完全バックアップでも全面移行でもない。
ここでは私的なファイルの内容や使用状況を判定していない。

| 情報の種類 | 現在の候補／Dailyで扱う範囲 | 切替までに決めること |
| --- | --- | --- |
| 実績・日付・摘要・postings・識別子 | 訂正済み状態へまとめ、元入力版は別に保全 | IDと必要な参照を守り、正確な量・通貨を保つ。新しい正データに永久の訂正鎖は不要 |
| 実際の返金／反転の対応 | 変換対象の対応を保持。UI作成は未接続 | 訂正として消さず、必要な日常操作と一緒に引き継ぐ |
| 予定と支払いの対応 | 対象内の現行予定・支払いリンク。置換元／取消済み等を現行予定から外す | 先々の必要な予定・管理情報を含める範囲を別途確認。候補の一覧だけで網羅性を主張しない |
| 現在量・起点・観測の根拠 | 対象内のゼロ起点、開始根拠、観測群、存在根拠を保持 | 不明をゼロにしない。過去の完全性は別に扱う |
| 科目の許可語彙・表示・通貨の小数桁 | 限定した設定を保持 | その他の表示・選択・役割設定も必要か確認。小数桁で量を再解釈しない |
| 役割、予算配分、Actual/Scheduledの用途、期間・周期・網羅性 | 今の候補では未変換 | 使用する回答に必要な情報を移す／明示して後で扱う。未変換を不存在にしない |
| 店舗、元金額、両替、関係・精算等の追加根拠 | Dailyには両替等の一部の器があるが、既存の候補コンバータは追加実績根拠を拒否する | 画面・形式・コンバータそれぞれの対応を確認。新しい器があるだけで移行済みにしない |
| Attentionその他の家庭情報・設定 | 今の候補では未変換 | 実際に必要なものを選び、持ち越し／読み取り専用保全の扱いを決める |

画面を後回しにすることと、その情報を捨てることは違う。
残りは元データ／必要なバックアップに保全し、後回しの間にどう参照・記録するかを明示する。
普段の実績記帳を二重化したり、自動同期して解決したことにはしない。

## 切替範囲を確定する手順

1. **この表をユーザーと仕分ける**：「切替前に必須／切替後でよい／使わない」を選ぶ。
   最初は下の五つの質問を決め、該当IDへ反映すればよい。全行を一度に判断する義務はない。
   手作業や外部道具で当面代替するものには、その方法を短く添える。未決定は未決定のまま残す。
2. **合意した必須の生活操作を実装する**：R02、予定管理・実績化、B01を開始候補とし、順番も決める。
   不足の共通処理だけ足し、任意の棚卸し行をpitの自動実装キューへ入れない。
3. **必須分だけで一周試す**：合成データで複数行の記帳・再開・訂正、予定の作成・変更・取消・支払い、
   口座×通貨の残高確認を行う。使う外貨・精算・予算があればその操作を加える。
4. **データと運用を確認する**：必要な情報・設定の持ち越し範囲、元データの保全、読戻し、
   バックアップからの復元、失敗時の確認方法を決めて試す。選んだ答えについて独立した期待値で照合する。
   永久ログ、LOAMと同じ保存機構、全研究ツールの再実行は条件にしない。
5. **ユーザーが切替を明示的に決める**：それまではLOAMが正。切替日・記帳先・保全元を確認し、
   pitが「実装できたから移行済み」と判定しない。
