# OCamlの学習メモ（任意）

Bakhloの既存コードを読むための補助メモ。家計簿を便利にすることが目的で、
学習パターンを実演するために機能・抽象化・ドキュメントを増やす必要はない。
現在の作業は[HANDOFF](HANDOFF.md)を参照する。

## 小さな型から読む

- [`identifier.mli`](../lib/identifier.mli)：通貨と科目などを別の型で扱う。
  型の違いは取り違えを防ぐが、実在する口座や正しい入力だとは保証しない。
- [`quantity.mli`](../lib/quantity.mli)：Zarithの任意精度整数で数量を扱う。
  表示の小数点と通貨換算は別の問題。
- [`movement.mli`](../lib/movement.mli)：明示された効果の非ゼロ・単一通貨・収支一致を検査する。
  `Ok` はこの検査に通った値であり、家計の事実や保存成功の証明ではない。

## 計算と入出力を分ける

`lib/` と `application/` は与えられた値を検査・計算する。
`bin/` などの外側がファイル、時刻、表示を扱う。役割を分けるために、
汎用サービス層や効果フレームワークを新設する必要はない。

## S式の読取

[`sexp/book.mli`](../sexp/book.mli)の `of_string` は現在の限定形式を読み、
参照や数量の整合性を検査する。`candidate` は検査済みの変更候補であって、
ファイルの安全な更新や耐久性を保証する型ではない。

既存Bookは追記した訂正関係から現在の明細を選ぶ。これはその形式の実装であり、
Bakhloが永久に訂正履歴を正データに持つという製品要件ではない。
新しい候補は訂正済み明細を使い、修正前を別の元データやバックアップに残せる。
返金など実際の取引は、入力の修正と区別する。

## テストと移行

既存のexpectテストと独立したモデルを、変更した箇所に応じて使う。
テストの通過は未検査の運用や全データの正しさまで保証しない。

`loam_read/` は限定されたLOAM読取で、予定や全家計データをBookへ変換する
完成済み移行ツールではない。残高が一致しても、日付・科目・明細・予定との対応が
保たれるとは限らない。元データを残し、必要な対応を確認してから切替を決める。
